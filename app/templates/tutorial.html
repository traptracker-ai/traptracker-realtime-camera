Run on your own machine only. TrapTracker RT has no login and stores your email app password locally. The default setup publishes it on localhost only — keep it that way unless you've secured access yourself.

What it does

TrapTracker RT watches an email inbox your trail cameras send photos to. When a new image arrives it downloads the photo, identifies the species with an AI model, checks it against your watch-list, and emails your stakeholders the labelled image when a watched species is detected. Everything is organised into projects.

Setup steps

1 · Add your model(s)

Put your .onnx model and its matching .txt class list (same base name) in models/single-stage-detectors/, or a two-stage DeepFaune pair in models/two-stage-detectors/. Add as many as you like — each project picks one.

2 · Start the app

You do not need a GPU. The default build runs on any computer (Windows, Mac including Apple Silicon, or Linux) using the CPU.

Default (CPU, recommended): docker compose up --build
GPU (optional, NVIDIA only): docker compose -f docker-compose.gpu.yml up --build

The GPU build needs an NVIDIA GPU, current drivers, and the NVIDIA Container Toolkit on the host. Either way, the app tries the GPU first and falls back to CPU automatically if it can't be used, noting the reason in the monitoring log. Then open http://localhost:8502. You can see whether it's on GPU or CPU in the System Status box in the sidebar.

GPU compatibility. Tested on NVIDIA RTX A6000 · Driver 573.73 · CUDA 12.8. Minimum: NVIDIA driver ≥ 525 (CUDA 12.x capable), x86_64. The image targets CUDA 12.x / cuDNN 9.x (onnxruntime-gpu 1.19.2). Check yours with nvidia-smi — if CUDA Version reads 12.x, the GPU build will work.

3 · Prepare a camera email account

Use a dedicated Gmail for your cameras. Turn on 2-Step Verification, create an App Password (for "Mail"), and enable IMAP in Gmail settings. You'll use the 16-character app password — not your normal password.

4 · Create a project

Click New Project, name it, and choose its detection model.

5 · Add cameras

Each camera is identified by a token in the email subject, written between = signs, e.g. Trail cam (=Camera01=). Add a camera whose Name (or Routing key) matches that token. Only emails with a matching token are processed.

6 · Configure the email source

Enter the camera mailbox address and app password. Gmail defaults: IMAP imap.gmail.com:993 (SSL), SMTP smtp.gmail.com:587 (STARTTLS). Save, then use Send test email to confirm — ideally to a different address than the sender.

7 · Build your watch-list

Pick the species to be alerted about from the dropdown (drawn from your model's classes) and set a minimum confidence (0.50 is a good start).

8 · Add recipients

Add everyone who should receive alert emails. Each gets the labelled image attached.

9 · Start monitoring

Click Start monitoring and watch the live log. The app runs continuously and resumes automatically if the computer restarts. Use the Gallery to review processed images.

How the flow works

1Camera takes a photo
2Camera emails it, subject contains (=Camera01=)
3TrapTracker RT polls the mailbox (~every 30s) and matches the token to a camera
4Downloads the image and runs the AI model
5If a watch-list species is detected above its confidence, emails all recipients the labelled image

Troubleshooting

Build error "No matching distribution found for onnxruntime-gpu": you're building the GPU image on a machine that can't use it (often an Apple Silicon Mac or ARM server). Use the default CPU build: docker compose up --build.

Missing GPU / NVIDIA driver / CUDA version errors: the GPU build needs an NVIDIA GPU, current drivers, and the NVIDIA Container Toolkit on the host. If you don't have all three, use the default CPU build. A running GPU build also falls back to CPU automatically and logs why.

Port 8502 already in use: change the published port in the compose file (e.g. 127.0.0.1:8600:8501) and open http://localhost:8600.

"Alert sent" but no email: check Spam / All Mail in the recipient inbox; mark "Not spam" or add a filter. Test with a recipient different from the sender.

IMAP login failed: confirm you used the App Password (not the account password) and that IMAP is enabled. Fix settings, then Stop and Start again.

No species in the dropdown: the model's .txt class list is missing or misnamed — it must match the .onnx base name.

Images not picked up: the subject must contain (=CameraName=) matching a camera you added.

Check what the app sees: visit /healthz for detected models.
